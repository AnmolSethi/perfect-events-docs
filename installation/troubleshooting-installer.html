Troubleshooting the Installer

Symptom, cause, fix — for the most common install-time problems.

The Requirements step won't turn green

Symptom: One or more items on the Requirements screen stays red.
Cause: A PHP extension is missing, or you're on PHP < 8.3.
Fix: Check with your host how to enable the missing extension (cPanel: "MultiPHP INI Editor" or "Select PHP Version" → extension checkboxes; VPS: apt install php8.3-<ext> then restart PHP-FPM). Either GD or Imagick satisfies the image requirement — you don't need both.

The Permissions step won't turn green

Symptom: storage/, bootstrap/cache/, or .env shows as not writable.
Cause: Upload tools sometimes preserve restrictive permissions, or the web server runs as a different user than the one that uploaded the files.
Fix: chmod -R 775 storage bootstrap/cache (or 755, depending on your host's ownership model), and make sure the folder containing .env is writable if .env doesn't exist yet. On shared hosting, re-uploading via File Manager rather than FTP sometimes fixes ownership mismatches outright.

"Test connection" fails on the Database step

Symptom: Database step won't proceed even with correct-looking credentials.
Cause: Almost always one of: wrong host (shared hosting is often localhost, not 127.0.0.1, or vice versa), the database user hasn't been granted privileges on that specific database yet, or the DB name/user needed your cPanel account's prefix (e.g. cpaneluser_dbname).
Fix: Double-check the exact values from cPanel → MySQL Databases, including the prefix. On a VPS, confirm mysql -u youruser -p -h host database works from the same server first.

"Send test email" fails on the Mail step

Symptom: Test email never arrives, or the button shows an error.
Cause: Wrong port/encryption combination is the most common one — port 587 wants tls, port 465 wants ssl. Some hosts also block outbound port 25/587 entirely.
Fix: Confirm the port+encryption pairing with your mail provider. You can also just skip this for now (leave the driver as log) and configure real SMTP later from Admin → Settings → Mail — it isn't required to finish installing.

Blank page / 500 error after finishing the wizard

Symptom: The Done screen never appears; you get a blank page or a generic server error.
Cause: Usually a PHP error during the Run step's migration/seed — check your host's PHP error log (cPanel: "Errors" in the file manager, or storage/logs/laravel.log if it got far enough to write one).
Fix: The Run step is safe to retry — fix whatever the log points at (commonly a missing extension that Requirements somehow didn't catch, or a database privilege gap) and reload /install; it'll resume from wherever it left off rather than starting over.

Installed site redirects back to /install

Symptom: Visiting your domain after a successful install redirects back to /install.
Cause: The install lock (storage/app/installed.json) was deleted — often by a "clean" redeploy that didn't preserve the storage/ folder, or by a backup restore that only restored the database and not the filesystem.
Fix: Since your installations database row is likely still intact, don't re-run the full wizard (it would try to re-seed). Restore storage/app/installed.json from a backup if you have one; if not, this is a support-ticket situation rather than something to work around by hand.

Still stuck? See the full troubleshooting index for issues outside the installer itself.
