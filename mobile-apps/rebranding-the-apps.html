Rebranding the Apps

The rebrand kit sets icon, splash, display name, and package id — one run per app.

Most of an app's brand — its in-app name, logo, colors, support email — is already Admin-configurable at runtime, no rebuild needed (see Admin-configurable vs. rebuild). The rebrand kit exists for the handful of things a store listing and the OS itself need baked into the compiled app: launcher icon, splash screen, the name shown under the icon, and the Android/iOS package id. Run it once per app before you build for release.

1. Prepare your assets

A 1024×1024 PNG icon (no transparency for iOS), and optionally a splash logo image.

2. Copy the example config

Each app carries its own copy of the kit. Run these from inside the app's folder:

cd flutter/apps/customer
cp tool/rebrand/customer.example.yaml tool/rebrand/customer.yaml

cd ../scanner
cp tool/rebrand/scanner.example.yaml tool/rebrand/scanner.yaml

3. Edit the config

In tool/rebrand/customer.yaml (and separately for scanner.yaml), set the app name, package id, and the path to your icon (relative to the config file itself, or absolute). Each app needs its own values — a customer ticketing app and a staff scanning app shouldn't share one package id or store listing.

4. Run it

cd flutter/apps/customer && dart run tool/rebrand.dart customer
cd flutter/apps/scanner  && dart run tool/rebrand.dart scanner

Add --dry-run first to preview the plan without changing anything. Each step (icon, splash, rename) is independent and safe to re-run if one fails partway — just fix the reported error and run it again. Only apps/<app>/android and apps/<app>/ios are touched.

Still manual after running this

  • Firebase — replace google-services.json and GoogleService-Info.plist with your own project's files, per app. Push notifications silently stay off until you do. See Firebase & push.
  • iOS signing — open apps/<app>/ios/Runner.xcworkspace in Xcode, pick your own team under Signing & Capabilities, confirm the bundle id matches your config. A Mac is required — there's no way around this for iOS.
  • Store listings — changing the package id after you've already published creates a brand-new listing rather than renaming the existing one. Decide your final package id before your first submission.
  • Native permission strings (e.g. the camera-usage description the scanner app shows) — edit Info.plist/AndroidManifest.xml directly if you want different wording; the defaults work for most buyers.
  • Android's namespace (in build.gradle.kts, distinct from applicationId since AGP 8) is left as-is by the kit — edit it by hand too if you want it to match your new applicationId. A mismatch is valid and builds fine either way.

Troubleshooting

"Config file not found" You need to copy the .example.yaml to a plain .yaml first (step 2) — the example file itself is never read directly.
"Icon file not found" / "Splash image not found" The path in your config is relative to the config file's own directory, not to flutter/.
