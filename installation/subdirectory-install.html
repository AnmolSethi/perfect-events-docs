Installing in a Subdirectory

Running PerfectEvents at example.com/events instead of its own domain.

PerfectEvents can run at a path like example.com/events instead of owning a whole domain, but the web server's document root still has to point at script/public — you can't just drop the whole app folder inside your existing site's public folder and expect it to route correctly.

Apache (cPanel-style)

Create an "Addon Domain" or subdomain pointed at a folder, upload PerfectEvents there, and set that folder's document root to its public subfolder — same as a full domain install (see cPanel), just mapped under a path instead of the domain root. A true "subfolder of an existing document root" setup (e.g. an existing Apache vhost serving example.com, with PerfectEvents at /events underneath it) needs an Alias directive pointing /events at script/public, since Laravel's own routing has no concept of a URL prefix without one:

Alias /events /var/www/perfectevents/public
<Directory /var/www/perfectevents/public>
    AllowOverride All
    Require all granted
</Directory>

Nginx

location /events {
    alias /var/www/perfectevents/public;
    try_files $uri $uri/ @events;
}
location @events {
    rewrite ^/events/(.*)$ /events/index.php?$1 last;
}
location ~ ^/events/index\.php$ {
    fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    fastcgi_index index.php;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root/index.php;
    fastcgi_param SCRIPT_NAME /events/index.php;
}

Set the app URL

Whichever route you take, set APP_URL (in the wizard's Application step, or later in .env) to the full path including the subdirectory — https://example.com/events — so generated links, assets, and redirects come out correct.

Simplest option If your host supports subdomains easily, a subdomain (events.example.com) avoids all of the rewrite-rule complexity above and is worth considering over a true subdirectory.
