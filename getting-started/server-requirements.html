Server Requirements

What your host needs before you unzip the installer.

PerfectEvents runs on any host that can run a modern Laravel application: shared hosting with cPanel, a VPS, or a container platform. There's nothing exotic in the requirements — no headless browser, no Node.js at runtime, no separate search service.

Server software

RequirementVersion
PHP8.3 or newer
MySQL8.0 or newer (MariaDB is not supported — the schema uses MySQL 8–specific JSON functions and generated columns)
Web serverApache with mod_rewrite (shared hosting) or Nginx
DiskA few hundred MB for the app itself, plus room for uploaded media (event covers, organizer logos) — budget for growth same as any media-heavy site

Required PHP extensions

Standard for any current Laravel app, plus two the platform specifically needs:

  • BCMath, Ctype, cURL, DOM, Fileinfo, Filter, Hash, Mbstring, OpenSSL, PCRE, PDO + pdo_mysql, Session, Tokenizer, XML
  • GD or Imagick — required for event/organizer image thumbnails (cover, card, and social-share sizes are generated automatically on upload)
  • intl — used for currency and date formatting across locales

The install wizard checks all of these automatically on its first screen and tells you exactly what's missing before you can continue — see the wizard walkthrough.

File permissions

The web server user needs write access to storage/ and bootstrap/cache/ — identical to any Laravel app. On shared hosting this is usually already correct for anything under your account; the installer's requirement checker will flag it if not.

Background processing

Two things need to run outside the request/response cycle: a cron entry (one line, every host supports this — including shared hosting) and a queue worker (ticket PDF generation, emails, image conversions, and push notifications are all queued so checkout stays fast). See Cron & queue workers for exact setup on shared hosting vs. a VPS with Supervisor.

Outbound HTTP

The server needs to make outbound HTTPS requests to whichever payment gateways, SMTP/SMS provider, and (if used) Firebase project you configure — most shared hosts allow this by default, but a locked-down VPS/firewall may need an explicit allow rule.
