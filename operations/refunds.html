Documentation / Operations

Refunds

Whole-order refunds, gated by a configurable window, always audit-logged.

Refunds are issued from an order's detail page — either the Admin or Organizer panel, same underlying action either way (an organizer can refund their own orders without needing an admin).

What a refund does

  1. Calls the original payment gateway to actually return the money.
  2. Records a refund row against the order.
  3. Releases the order's ticket inventory and coupon redemption back to sale.
  4. Voids the order's tickets (they stop scanning as valid) and notifies the buyer.

Every refund is written to the audit log automatically — no separate step, and no way to issue one that doesn't get logged, regardless of whether it came from the Admin panel, the Organizer panel, or the API directly.

What can be refunded

Only a paid order (or one already partially refunded) is eligible. Refunds are whole-order only in this version — there's no partial/per-ticket refund yet, so if a buyer wants to return 2 of 4 tickets, that's a manual conversation outside the tool for now.

The refund window

Admin → Settings → General has a refund window (in days; 0 means unlimited). Once an order is older than that window, refunding it through the panel is blocked — this exists to stop a refund being issued for an event that's already happened and been attended.

Refunds and checked-in tickets Refunding an order voids its tickets. If someone's already been scanned in at the door and you refund their order afterward, their ticket becomes invalid retroactively — make sure that's the outcome you actually want before refunding a same-day order.
