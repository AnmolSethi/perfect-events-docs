Multi-Country & Multi-Currency

Pricing, tax, fees, and payment methods, all resolved per currency and per country — never one hard-coded assumption for the whole platform.

Everything money-related in this product is driven from two small reference tables — Admin → Currencies and Admin → Countries — plus the country-and-currency-specific overrides layered on top of them. A fresh install ships with just USD active and no country-specific overrides, and behaves exactly like a single-currency platform until you configure more. Nothing below is required reading for a single-country, single-currency install.

Currencies

Admin → Currencies is the source of truth for how money renders everywhere — symbol, decimal places, thousands/decimal separators, and whether the symbol sits to the left or right of the amount. Every platform (web, PDFs, emails, both Flutter apps) formats a given amount identically because they all read from this same table via /api/v1/config. Activate as many currencies as you like; organizers price each event's ticket types in whichever active currency they choose, and every ticket type on one event must share the same currency — checkout rejects a basket that somehow mixed them.

Countries

Admin → Countries is a reference list (code, name, dial code) used by venue address forms, the buyer phone-number picker, and event discovery's country filter. It's pure reference data — adding a country here doesn't change any pricing or tax behavior by itself.

Tax Rates

Admin → Tax Rates lets you set a tax rate (VAT, GST, sales tax — whatever you label it), inclusive or exclusive, per country. At checkout, the applicable rate is looked up by the event's venue country — not the buyer's billing address, since this product doesn't collect one. An event with no venue, or a venue in a country with no configured rate, falls back to the single global rate in Admin → Settings → General. Whatever rate actually applied is stamped onto the order at checkout time, so changing a country's rate later never rewrites a past order's receipt.

Place-of-supply tax only This resolves tax by where the event happens, which covers the common case (a ticketed event has a physical or nominal venue location). Buyer-location-based tax rules (e.g. some digital-services VAT regimes) aren't modeled — there's no buyer billing address anywhere in this product to base that on.

Currency Fees

Admin → Currency Fees overrides the platform service fee (percentage + fixed amount, normally set in Settings → General) for one specific currency. You'll usually only need the fixed-amount half: a flat "50" fixed fee is 50 cents in USD but a very different real amount in a currency with different decimal places (0 for JPY, 3 for BHD/KWD/OMR). Leave either number blank to keep using the general value for just that half.

Organizer defaults

An organizer's Profile page has an optional home country and default currency. Neither is required, and neither restricts what an organizer can actually do — they're pre-fills only: a new event's currency dropdown defaults to the organizer's own default currency instead of the platform default, once set.

Payment gateway compatibility

Each payment gateway declares which currencies it can actually settle — Stripe and PayPal accept any; Razorpay is INR-only; Paystack covers NGN/GHS/ZAR/KES/USD. Checkout only ever offers a gateway that supports the order's currency, and the payment layer itself rejects a mismatched attempt even if bypassed at the UI level — this can't be worked around by editing a Blade view or the Flutter app, since the compatibility list lives on the gateway class itself, not the presentation layer.

Discovery & coupons

Buyers can filter events by country in the public site and the customer app, alongside the existing city filter. Coupons follow one rule: a percentage coupon works across any currency; a fixed-amount coupon is scoped to one currency (chosen when you create it) and simply won't apply to an order in a different one.

Payouts stay manual regardless None of the above changes how payouts work — see Payouts. An organizer running events in more than one currency simply accumulates a separate balance per currency and requests payouts against each one; there's no currency conversion anywhere in this product.
