Installing on cPanel / Shared Hosting

Domain root pointed at a subfolder, one cron line, no SSH required.

PerfectEvents was specifically designed to work on ordinary shared hosting — no Composer, no Node, no SSH, no Supervisor. The default settings (QUEUE_CONNECTION=database, SESSION_DRIVER=database, CACHE_STORE=database) exist for exactly this case.

1. Upload

Upload the script/ folder's contents to your account (via File Manager's zip-upload or FTP). Most cPanel setups serve a domain from public_html/, but Laravel needs its web root to be script/public, not the app root. Two common ways to handle this:

  • "Application root" hosting (recommended, if your host offers it) — some cPanel setups let you point the domain's document root directly at a subfolder. Upload everything to e.g. perfectevents/ outside public_html, and set the domain's document root to perfectevents/public.
  • Manual split — upload everything to a folder above public_html (e.g. app/), then move only the contents of app/public into public_html, and edit public_html/index.php's two require paths to point up to ../app/vendor/autoload.php and ../app/bootstrap/app.php.

2. Create the database

In cPanel → MySQL Databases: create a database, a user, and grant that user all privileges on the database. You'll enter these three values in the wizard's Database step.

3. Run the installer

Visit your domain — you'll land on /install automatically. Follow the wizard walkthrough.

4. Add the cron entry

cPanel → Cron Jobs → add a new job, run every minute:

* * * * * php /home/youruser/perfectevents/artisan schedule:run >> /dev/null 2>&1

Use the full absolute path to your script/artisan file and whatever PHP binary your host provides for CLI (check with your host if php alone doesn't resolve to 8.3+ — many shared hosts need something like /usr/local/bin/php83). This single line covers everything scheduled — including keeping the queue moving; see Cron & queue workers for what actually runs off it.

5. HTTPS

Enable AutoSSL (or your host's equivalent) and make sure APP_URL in .env uses https:// — the app tightens session-cookie security automatically once it does. See HTTPS.

No SSH? No problem Everything above is doable entirely through cPanel's web UI. If you do have SSH, you can instead run php artisan migrate etc. manually, but nothing in this product requires it.
