Documentation / Integrations

Stripe

Card payments via PaymentIntents — set up in Admin → Settings → Payment gateways.

Configured entirely from Admin → Settings → Payment gateways → Stripe — no .env changes needed.

Keys you need

FieldWhere to find it
Secret keyStripe Dashboard → Developers → API keys. Starts with sk_test_ or sk_live_.
Publishable keySame screen, starts with pk_test_/pk_live_ — used client-side, safe to expose.
Webhook signing secretCreated when you register the webhook endpoint below — starts with whsec_.

Webhook URL

In Stripe Dashboard → Developers → Webhooks, add an endpoint:

https://yourdomain.com/api/v1/webhooks/stripe

Subscribe it to at least payment_intent.succeeded and payment_intent.payment_failed. Copy the signing secret it gives you into the Webhook signing secret field in Admin.

In the mobile app

The customer app pays with Stripe's own in-app payment sheet — cards, plus Apple Pay / Google Pay where the device supports them — so buyers never leave the app. It uses the publishable key above; nothing else to set up in the app. The order is confirmed by the webhook, exactly as on the website.

Test mode

Use your sk_test_/pk_test_ keys and Stripe's published test card numbers (e.g. 4242 4242 4242 4242, any future expiry, any CVC — see Stripe's own testing docs for the full set including 3D Secure and decline scenarios). Switch to sk_live_/pk_live_ — and re-register a live-mode webhook endpoint, Stripe keeps test and live webhooks separate — before accepting real payments.

Verify before you launch Use the "test" button next to the gateway in Admin — it validates your keys can actually reach Stripe before you flip the gateway to enabled.
