Backup & Restore Around an Update

The same manual backup process as always — just make sure you do it right before you touch anything.

This is the same process described in full on Backups — there's no in-app backup/restore tool at any point, including around an update. The only thing specific to an update is timing: take the backup immediately before you start, not "recently."

Before updating

  1. Database dump.
  2. storage/app/public (or confirm your S3 bucket needs no action — it isn't touched by a code update either way).
  3. Your current .env and, if you've made any, your customized files.

If an update goes wrong

  1. Restore the previous release's script/ code (keep it around until the update is confirmed working — don't delete the old version immediately).
  2. Restore the database dump you just took, not an older one — the goal is undoing the update, not losing work that happened since your last routine backup.
  3. Clear caches (php artisan config:clear etc., or Admin → System's button) and verify.
Migrations can be one-way Some database migrations aren't cleanly reversible (a column drop, a data transformation). Restoring your pre-update database dump is the reliable rollback path — don't rely on php artisan migrate:rollback alone for an update you're trying to fully undo.
