Localization & Adding a Language

Two separate systems — UI chrome strings, and per-event content translation.

There are two different kinds of "translation" in this product, handled two different ways.

1. UI chrome — admin/organizer panel and site labels

Buttons, labels, error messages — the fixed text around the product, not content an organizer wrote. This is what Admin → Languages and Admin → Translations manage.

Add a language

Admin → Languages → Add: enter a code (e.g. fr), display name, native name, whether it's right-to-left, and whether it's active. English is seeded by default and can't be deactivated or deleted. Only one language can be the default at a time — setting a new default reassigns it and activates that language automatically.

Translate it

Admin → Translations → pick the language → you'll see every UI string in the product next to its English default, with an editable box. Save a value to override it for that language; clear it back to empty to fall back to the English default again — there's no "half-translated" broken state, every untranslated string just shows English until you fill it in.

Export / import

Translations can be exported as JSON (the full effective set — your overrides plus English defaults for anything untranslated) and re-imported, so translation work can be done offline or handed to a translator and brought back in. Import validates every key against the known key catalog and ignores anything it doesn't recognize, so a malformed file can't corrupt the table.

2. Event/organizer content — per-locale fields on the content itself

Event titles and descriptions, FAQ answers, category names, and organizer bios are translated separately, directly on each model, editable per-locale right in that item's own editor (the event editor, the category editor, etc.) — not through the Translations screen. If you haven't entered a translation for a given locale, that content falls back to whichever locale it does have.

Mobile apps use bundled translations, not live ones The customer and scanner apps ship their own translation files built into the app — they don't fetch UI strings from the server at runtime. Changing a translation in Admin → Translations affects the website and panels immediately; it does not affect the mobile apps until their own translation files are updated and the app is rebuilt.
