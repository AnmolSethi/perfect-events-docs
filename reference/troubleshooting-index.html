Troubleshooting Index

The 10 most common issues first, then everything else by area.

If you're stuck, check these first

  1. Requirements/Permissions step won't turn green — a missing PHP extension or wrong file permissions.
  2. "Test connection" fails on the Database step — wrong host or a cPanel account-prefix mismatch.
  3. A published event isn't showing on the public site — usually still awaiting approval, or the organizer account itself isn't approved.
  4. A payment succeeded at the gateway but the order stays "pending" — almost always the webhook URL.
  5. Emails aren't sending — port/encryption mismatch, or still on the log driver.
  6. Admin → System shows a stale cron heartbeat — the cron entry isn't actually firing.
  7. Ticket PDFs/emails never arrive even though the order is paid — the queue isn't draining.
  8. Mobile push notifications never arrive — Firebase config mismatch, most often a wrong package/bundle id.
  9. A coupon code doesn't discount the order — it fails silently by design; check its eligibility rules.
  10. The site redirects back to the install wizard after already being installed — the install lock file went missing, usually from an incomplete restore/redeploy.

A published event isn't showing on the public site

Cause: Either the event itself is still Pending (awaiting admin approval) rather than Published, or its organizer account isn't Approved yet — an unapproved organizer can't have anything go public no matter what the event's own status is.
Fix: Check both independently in Admin — see Approvals.

A payment succeeded at the gateway but the order stays "pending"

Cause: Orders only move to paid when the gateway's webhook fires and verifies — the browser redirect back to your site after payment is a UX convenience, not what confirms payment. If the webhook URL isn't registered correctly, or its secret doesn't match, the webhook is rejected and the order never updates even though the buyer was actually charged.
Fix: Re-check the exact webhook URL and secret for that gateway against its integration page, and check the gateway's own dashboard for failed webhook delivery attempts (most providers log these with the exact rejection reason).

Admin → System shows a stale cron heartbeat

Cause: Your cron entry either isn't installed, points at the wrong PHP binary, or uses a relative/wrong path to artisan.
Fix: See Cron & queue workers — confirm the exact command with your host, including which PHP binary resolves to 8.3+ on their cron environment specifically (it's sometimes different from your shell's default php).

Ticket PDFs/emails never arrive even though the order is paid

Cause: Almost always the same root cause as above — if cron isn't running, the scheduled queue drain isn't running either, so queued jobs (PDF generation, email, push) pile up and never execute.
Fix: Fix the cron heartbeat first; queued jobs will drain on the next tick once it is. Admin → System also shows pending/failed job counts if you want to confirm the backlog directly.

Mobile push notifications never arrive

Cause: Most commonly a Firebase project mismatch — the app's bundled google-services.json/GoogleService-Info.plist doesn't match the project your server's FCM_CREDENTIALS service account belongs to, or the push channel is still off in settings.
Fix: See Firebase & push — double check the package/bundle id matches between the Flutter app and the Firebase project exactly.

A coupon code doesn't discount the order

Cause: This is by design, not a bug — an ineligible coupon (expired, not yet started, over its redemption limit, or below the minimum order amount) silently lets checkout proceed at full price rather than blocking the order.
Fix: Check the coupon's own rules in Admin/Organizer → Coupons — see Coupons.
