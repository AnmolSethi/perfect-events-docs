Documentation / Mobile Apps

Config Files

One JSON file tells the app which API to talk to, plus an optional Google Maps key.

Each app is pointed at your backend via a small JSON file passed at build/run time with --dart-define-from-file — not a .env file bundled into the app (which would ship its contents inside the compiled binary, readable by anyone).

config/prod.json.example

Each app has its own config/ folder (flutter/apps/customer/config and flutter/apps/scanner/config), so the two apps can point at different values.

{
  "API_BASE_URL": "https://your-domain.com/api/v1",
  "ENV": "prod",
  "APP_NAME": "Your App Name",
  "APP_ID": "com.yourcompany.events",
  "GOOGLE_MAPS_API_KEY": ""
}

Copy this to prod.json and fill in:

KeyValue
API_BASE_URLYour installed backend's /api/v1 URL. Required.
ENVprod for store builds.
APP_NAMEThe same name as Admin → Settings → Branding → App name. Only shown on a very first launch with no internet; after that the app uses the name from your settings.
APP_IDThe app's package name / bundle ID (the package_id from rebranding). Sent to map tile servers, whose usage policies ask apps to identify themselves.
GOOGLE_MAPS_API_KEYCustomer app, optional: your Google Maps key, needed only if you choose Google Maps in Admin → Settings → App → Maps. Leave it blank to use tile maps. This key ends up in the app, like every mobile maps key, so restrict it to your app in the Google Cloud console. See Maps & venue locations.

prod.json isn't committed (it's your real endpoint), only the .example is.

config/dev.json

Same shape, for local development against a dev/staging backend — create this yourself, typically pointing at http://localhost:8000/api/v1 or a staging URL. Not committed either.

Everything else comes from the API, not a config file

Brand name, logo, colors, enabled languages/currencies/payment gateways — the app fetches all of that from GET /api/v1/config on launch (cached locally, with a bundled fallback for offline first-launch). Changing your brand color in Admin → Settings takes effect in the app the next time it launches, no rebuild required. See Admin-configurable vs. rebuild for exactly where the line is.
