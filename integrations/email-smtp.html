Email (SMTP)

Every transactional email — receipts, verification, reminders — goes through this.

Set from Admin → Settings → Mail (or the install wizard's Mail step, which seeds the same fields). Used for: email verification links, password resets, order receipts and ticket delivery, event reminders, and refund/payout notifications.

Fields

FieldNotes
Driversmtp for real delivery; log writes emails to the log file instead of sending (useful only while testing, never for a live site).
Host / PortYour provider's SMTP hostname and port — see common pairings below.
Encryptiontls for port 587, ssl for port 465.
Username / PasswordYour SMTP account credentials — for API-based providers (see below) this is usually a fixed username plus an API key as the password.
From address / From nameWhat recipients see as the sender.

Use the "send test email" button before relying on it — a bad host/port/encryption combination otherwise fails silently until a real customer doesn't get their tickets.

Common providers

ProviderHostPort / Encryption
Gmail / Google Workspacesmtp.gmail.com587 / tls (requires an app password, not your account password)
SendGridsmtp.sendgrid.net587 / tls (username is literally apikey)
Mailgunsmtp.mailgun.org587 / tls
Amazon SESemail-smtp.<region>.amazonaws.com587 / tls
Your host's own mail servere.g. mail.yourdomain.com587 / tls or 465 / ssl — check with your host
Set up SPF/DKIM with your provider This is outside the app's control, but without it, a meaningful share of transactional email (including ticket delivery) ends up in spam. Follow your SMTP provider's domain-verification steps.
