Firebase & Push Notifications

Server-side credentials in .env, per-app config files in Flutter — two separate setups.

Push notifications need setup in two places: the Laravel server (to send pushes) and each Flutter app (to receive them). Neither is required for the rest of the product to work — push is an optional channel, off by default.

1. Server side (Laravel)

  1. In the Firebase console, open your project → Project settings → Service accounts, and generate a new private key. This downloads a JSON file.
  2. Upload that JSON file somewhere on your server outside the public web root, and add its path to .env: 
    FCM_CREDENTIALS=/absolute/path/to/firebase-service-account.json
  3. Optionally set FCM_PROJECT_ID if you want to override the project id — normally it's read straight from the service-account file, so this is rarely needed.
  4. Turn the push channel on (alongside SMS/email) in notification settings.

If the credentials file is missing or unreadable, the app doesn't error — it simply treats push as unconfigured and skips that channel silently, so a half-finished setup never breaks anything else.

2. Each Flutter app needs its own Firebase project

The customer app and the scanner app are separate Firebase projects (or at minimum separate registered apps within one project) — set each one up independently via the FlutterFire CLI or the Firebase console:

AppAndroid fileiOS file
Customerflutter/apps/customer/android/app/google-services.jsonflutter/apps/customer/ios/Runner/GoogleService-Info.plist
Scannerflutter/apps/scanner/android/app/google-services.jsonflutter/apps/scanner/ios/Runner/GoogleService-Info.plist

The repo ships with placeholder Firebase config for its own demo project — replace both files per app with your own before building for release. This is one of the values that requires a rebuild, not an Admin setting — see Admin-configurable vs. rebuild.

Test before you ship Send a test push to a debug build of each app once its config files are in place, before doing a release build — a wrong package name/bundle id in Firebase vs. the app itself is the most common reason pushes silently never arrive.
