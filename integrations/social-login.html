Documentation / Integrations

Social Login

Google, Apple, and Facebook — each toggled and keyed independently.

Configured per-provider from Admin → Settings → Social login. Three providers are supported: Google, Apple, Facebook — each with its own enable switch and its own client ID/secret.

Fields (per provider)

FieldNotes
EnabledTurns the login button on/off on the site and in the apps for that provider specifically.
Client IDFrom the provider's own developer console.
Client secretSame place — keep it private.

Redirect / callback URL to register with each provider

https://yourdomain.com/auth/{provider}/callback

Substitute google, apple, or facebook for {provider}. Register this exact URL in each provider's console (Google Cloud Console → Credentials; Apple Developer → Sign in with Apple; Meta for Developers → Facebook Login) or the callback will fail with a redirect-URI-mismatch error.

How linking works

A social sign-in is matched to an existing account by email address if one already exists (so a buyer who registered with email/password and later clicks "Continue with Google" using the same address links to the same account, rather than creating a duplicate), and creates a new account otherwise.

Apple has extra requirements "Sign in with Apple" requires your own Apple Developer account, a registered Services ID, and a generated private key/JWT for client secret rotation — Apple's setup has more moving parts than Google or Facebook. Follow Apple's own Sign in with Apple documentation for generating those credentials; what you paste into Admin is the same client ID / secret concept either way.
