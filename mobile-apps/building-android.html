Building Android (AAB)

A signed app bundle, ready for the Play Console.

Do this once you've rebranded the app and set your real production API URL.

1. Generate a signing key

If you don't already have one for this app:

keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload

Store this file and its passwords somewhere safe and durable — losing it means you can never publish an update to an already-live app under the same listing again. Play App Signing (below) softens this for future re-key scenarios but the upload key itself still matters.

2. Point Gradle at it

Create apps/<app>/android/key.properties (not committed) with your keystore path and passwords, and reference it from android/app/build.gradle.kts's signing config — standard Flutter/Android release signing, no product-specific step here. Flutter's own "Build and release an Android app" guide covers the exact Gradle wiring if you haven't set this up before.

3. Build

cd apps/customer   # or apps/scanner
fvm flutter build appbundle --dart-define-from-file=config/prod.json

Output lands at build/app/outputs/bundle/release/app-release.aab. Build each app separately — they're independent binaries.

4. Play App Signing

When you first upload to Play Console, opt into Play App Signing — Google re-signs your upload key with their own app-signing key for distribution, which means a lost/compromised upload key later is recoverable (you can request a reset) rather than catastrophic.

Test the bundle before submitting Use Play Console's internal testing track first — install the actual AAB on a real device via Play's internal app sharing before pushing to production review.
