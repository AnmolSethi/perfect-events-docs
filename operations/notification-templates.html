Notification Templates

Editable copy for every notification the platform sends, per channel and per language.

The platform sends 15 kinds of notification — order placed, tickets issued, payment failed, event reminders, refunds, payouts, and more — each potentially over multiple channels (email, in-app, push, SMS) and in multiple languages. Admin → Notification templates is where you edit the actual wording for each.

How a template is identified

Every template row is keyed by (notification key, channel, locale) — for example, "Payment successful + tickets" over "mail" in "es" is a different row from the same notification over "push", or the same channel in "en". You edit subject and body per row, and can turn any individual row off (falls back to the platform's built-in default text if you deactivate a custom one, so it's safe to try a rewrite without risking a broken/empty notification going out).

Placeholders

Each notification type supports a fixed set of {{placeholder}} tokens you can use in your subject/body — for example the tickets-issued email supports {{buyer_name}}, {{event_title}}, and {{ticket_count}}. The editor tells you which placeholders are valid for the row you're editing; an unrecognized token is just left as literal text rather than silently failing.

Which channels each notification can use

Not every notification supports every channel — order-placed, for instance, doesn't go out over SMS, only tickets-issued does (SMS also has to be turned on separately — see SMS — before any SMS row can actually deliver). The editor only shows channel rows that notification type actually supports.

This is wording, not workflow You're editing what a notification says, not adding new kinds of notification or new trigger conditions — the set of 15 keys is fixed. Adding a genuinely new notification type is a code change.
