Documentation / Maintenance

Updating the Product

Back up, upload the signed update package in Admin → System → Updates, done.

Every release comes with a ready-made update package. You install it from the admin panel — no FTP, no SSH, no re-running the install wizard, and your data, uploads and .env are never touched.

1. Find the package

In the release download, open the Updates/ folder. It holds:

FileWhat it's for
perfect-events-vX-to-vY.zipThe server update. Installs over exactly version X and takes you to Y. Upload this one in Admin.
perfect-events-mobile-vX-to-vY.zipOnly present when the apps changed: the changed flutter/ files plus a DELETED.txt. See Mobile apps below.

Your installed version is shown at the top of Admin → System → Updates. If you're more than one release behind, install each package in turn (X→Y, then Y→Z); a package refuses to install over any version other than the one it was built from.

2. Read the changelog

Check the changelog for every version you're crossing. Anything you have to do by hand — a new cron line, a raised PHP version, rebuilding the apps — is listed under that version's "Updating" note.

3. Back up

Take a database dump and a copy of storage/app/public (skip that if your uploads live on S3). See Backups. The updater backs up and restores the files it replaces by itself, but database changes can't be rolled back — that's what your dump is for. The Updates page won't start until you tick "I have a current backup".

4. Install

  1. Go to Admin → System → Updates.
  2. Tick the backup confirmation, choose the perfect-events-vX-to-vY.zip file and click Install.
  3. Keep the page open while it runs. It works in three short steps, one request each, so it fits inside a shared host's time limits:
    • Verifying — checks the package's signature, that it's newer than what you run and built from your version, that your server meets its requirements, that every file it will replace is writable, and that there's enough disk space.
    • Applying — turns on maintenance mode, backs up every file it's about to change, then swaps in the new ones.
    • Migrating — runs the database migrations, clears caches, records the new version and turns maintenance mode off.

If the page stops moving (a closed tab, a timed-out request), just reload it: an interrupted run resumes, or is rolled back to the previous files if it can't continue.

Only packages signed by the author install Each package is signed, and your copy checks the signature before it unpacks anything. A file that was altered, or didn't come from the official release, is rejected with "The package signature is missing or invalid".

If an update is refused

MessageWhat to do
Version … is not newer than the installed …You've already installed it. Nothing to do.
This incremental package applies to X, but Y is installedYou picked the wrong package. Use the one whose name starts with your installed version.
Requirements not metThe release needs a newer PHP version or extension. Upgrade it in your hosting panel, then retry.
These files were changed since the last update…You edited files the update also changes. Copy your edits somewhere safe, restore the originals, update, then re-apply them — see Preserving customizations.
The web server can't write to…Fix the permissions on the listed files so the web server user owns them, then retry.
Not enough free disk spaceThe updater needs room for the new files and a backup of the old ones. Free some space, then retry.
The upload is rejected as too largePackages up to 12 MB upload from the page. If your PHP upload_max_filesize / post_max_size are lower, raise them to at least 16M.

If a run fails after it started replacing files, every file is put back automatically and the page tells you so. In the rare case that restoring fails too, the site stays in maintenance mode and the message names the folder holding the backup — copy those files back over the install, then run php artisan up.

Built-in modules

Payments, SMS and Software Update are part of the product and update with it — they have no separate update or licence of their own. See Modules.

Mobile apps

The server update never changes the apps already installed on people's phones. When a release changes the apps, the changelog says so: apply the files from the mobile zip to your copy of flutter/ (delete the paths listed in DELETED.txt), re-apply your rebrand if it touched any of them, then rebuild and submit to the stores as usual — Android, iOS. Raise the build number each time; the stores reject one they've seen before.

Verify

Load the site, log into Admin, and place a test order if you have a gateway in test mode. Check that cron is still running (the heartbeat on Admin → System).
