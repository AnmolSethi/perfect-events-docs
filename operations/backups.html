Documentation / Operations

Backups

There is no in-app backup feature — back up at the hosting/database level instead.

No built-in backup/restore feature As of this release, PerfectEvents does not include an in-app backup or restore tool. Set up backups at the server/hosting level, the same way you would for any web application.

What to back up

  • The database — every order, ticket, event, and account record lives here. This is the part that matters most.
  • storage/app/public (or your S3 bucket, if you're using S3 storage) — uploaded media: event covers, organizer logos, branding assets.
  • .env — your app key and credentials. Losing this without a copy means losing the ability to decrypt anything the app encrypted (encrypted session/cookie data).

How to actually do it

  • cPanel / shared hosting — most hosts offer a "Backup" or "JetBackup" tool that handles both the database and files on a schedule; use it, or set up a cron-triggered mysqldump to a location outside your web root (and ideally off-server — an S3 bucket, or your host's remote backup destination).
  • VPS — a scheduled mysqldump plus a file sync (rsync/restic/etc.) of storage/app/public to off-server storage. Any standard Linux backup tool works; there's nothing PerfectEvents-specific about the backup itself.
  • Managed database (RDS, PlanetScale, etc.) — use the provider's built-in automated snapshots.

Restoring

Restore the database dump and the media files, and make sure storage/app/installed.json (the install lock — see Troubleshooting the installer) comes back too if your backup didn't already include the whole storage/ directory — a restore that only covers the database can otherwise leave the app thinking it isn't installed.
