Documentation / Mobile Apps

Admin-Configurable vs. Rebuild

The exact line between what changes instantly and what needs a new build, for the mobile apps.

Both apps fetch GET /api/v1/config on launch (cached, with a bundled fallback for offline first-launch), so a lot of "branding" is live and instant — change it in Admin, and it's reflected the next time the app opens, no store update required.

Admin — no rebuildRebuild — needs the kit and/or a new build
App name shown inside the app, brand colors (light/dark), logo, support linksStore-listing display name, launcher/app icon, splash image + native splash color
Enabled locales, translations, RTLBundled fonts
Enabled payment gatewaysFirebase project (google-services.json / GoogleService-Info.plist)
Feature flagsAPI base URL (baked in via --dart-define-from-file)
Android/iOS package id, native permission strings, deep-link / associated domains, signing
If you only need the left column You don't need the rebrand kit at all — just use Admin → Settings → Branding. The kit and a rebuild are only necessary if you're publishing your own store listing under your own identity (own icon, own package id) rather than using the apps as-shipped.

See Rebranding the apps for how to actually change the right-hand column, and Admin vs. rebuild for the same split as it applies to the website/panels rather than the apps.
