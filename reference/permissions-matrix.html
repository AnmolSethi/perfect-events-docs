Documentation / Reference

Permissions Matrix

Three fixed roles, seven permissions — custom roles are a planned V2 feature, not V1.

Roles are fixed in this version — admin, organizer, staff. Customers don't get a role at all; plain account type is enough for what a customer can do. Creating your own custom roles isn't available yet.

What admin can toggle

Admin → Roles & permissions lets you adjust which permissions organizer and staff are granted, from this fixed set of seven:

PermissionDefault grantsToggleable in Admin?
events.manage.ownorganizerYes
orders.view.ownorganizerYes
tickets.scanorganizer, staffYes
staff.manageorganizerYes
events.approveadmin only (structural)No — admin-only by design
settings.manageadmin only (structural)No — admin-only by design
payouts.approveadmin only (structural)No — admin-only by design

The admin account type bypasses permission checks entirely rather than being granted these as stored rows — "admin can do everything" is structural, not a setting you could accidentally turn off.

Edits you make here are preserved across updates/reseeds — the underlying seeder only applies its defaults the first time a role has zero permissions, so re-running it never clobbers a change you've made.

How this differs from API token abilities

Roles/permissions govern what an authenticated user can do inside the panels and API. Sanctum API tokens carry a separate, coarser ability (admin/ organizer → everything, staff → scanning only, customer → viewing their own tickets) checked at the route-middleware level before a permission check is even reached — see the API overview.
